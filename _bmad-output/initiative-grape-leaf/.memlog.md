- (requirement) R1 (SPEC §1, §2, §7): A farmer can scan a canopy on foot or from a mount and see the latest boxes labeled with the pack class and score, and the scan keeps running when the preview is hidden or the screen is off. Met when a running session shows those boxes and still runs after the preview is hidden or the screen is off.
- (requirement) R2 (SPEC §2, §8, §9, §10): Each new sighting becomes one event with class, confidence, canopy position, accuracy, speed, bearing, and at most one full-frame photo and one thumbnail. The same class within the configured distance and time stays that event and keeps its photo. Met when a known replay writes one row and one image, and a nearby repeat does not write a second row.
- (requirement) R3 (SPEC §2, §14): The farmer can open a finished session on an offline map and in a list, filter by class, plot, and feedback, mark an event correct, wrong, or unsure, and open its canopy point in another maps app or read bearing and distance. Met when this works with no network, and with no tiles the list still works.
- (requirement) R4 (SPEC §2, §14): The farmer can export that session as GeoJSON, CSV, KML/GPX, and a zip of images, and hand the file off through the Android share sheet. The session stays on the phone. Met when each format is produced and the share sheet opens.
- (requirement) R5 (SPEC §2, §11): While the farmer is moving, the app shows the sentence high disease pressure here when events per meter cross the configured threshold, and the review map flags that segment with density and severity as separate values. A scan that is not moving does not raise the alert. Met when a moving replay crosses the threshold and a stationary one does not.
- (requirement) R6 (SPEC §2, §6, §12, §13): The farmer can import a model pack from local storage with no network, or start an optional Wi-Fi download that installs only after the checksum matches. The app selects the largest installed tier that holds the configured frame rate, and the farmer can override that choice for the next session. If the smallest tier cannot, the app says so and still opens a scan. Met when a bad checksum leaves the previous pack in place and a local import is enough to scan.
- (requirement) R7 (SPEC §2, §6, §15): A developer can point the same scan path at a video and a GPX file, use a stand-in or scripted detector, and read the debug figures. A fixed image set run in the app matches a reference run closely enough to catch preprocess mismatches. Met when replay yields the same kind of overlay and events as a camera session and the stand-in parity check passes.
- (requirement) R8 (SPEC §17 milestone 9): A trained grape-leaf pack can replace the stand-in, pass that same parity check, and be accepted by a field comparison against ground truth. Met when that pack is the active pack on a real row and parity passes. It waits on the trainer project.
- (constraint) C1 (SPEC §3.1, AD-9): Capture, review, and export work with no network. The only network use is an optional, user-visible pack download on unmetered Wi-Fi. There is no telemetry, account, or sync.
- (constraint) C2 (SPEC §3.2, §3.3, AD-9): The app has no Play services dependency, including transitively, and the APK is sideloaded. Fused location is not a dependency of the app.
- (constraint) C3 (SPEC §3.4, architecture stack): minSdk is 26 and targetSdk is 37.
- (constraint) C4 (SPEC §3.5, AD-4): The model favors precision, so a track ends only when its configured max age is exceeded, not because a frame had no detections.
- (constraint) C5 (SPEC §3.6, AD-3, DESIGN): Classes, colors, score thresholds, and preprocessing come only from the model-pack manifest. Class color is not a theme token.
- (constraint) C6 (AD-1): The foreground service is the only capture pipeline. Replay and the scripted detector are port implementations. The UI does not detect, own tracks, or write events.
- (constraint) C7 (AD-2): core-model, tracking, density, and export import no Android APIs. Inference, camera, location, and data depend on core-model and not on each other.
- (constraint) C8 (AD-5, AD-6): Tracking decides create, merge, and the best frame. Data is the only writer. A merge keeps the existing image. Export is a pure function of rows the app has loaded.
- (constraint) C9 (AD-7, AD-13): The stored position is the canopy point after the mount offset. The frame and the fix are joined on elapsed realtime, never on the latest fix or on UTC.
- (constraint) C10 (AD-8): Density counts unique events per meter traveled while speed is at or above the configured minimum. Severity is the separate per-segment box-area fraction.
- (constraint) C11 (AD-11): The app passes one immutable config snapshot into the other modules, and the session stores that snapshot. The key names are fixed. The numbers are tuned on phones.
- (constraint) C12 (AD-10): Inference goes through InferenceBackend, and only bundled runtimes are allowed. Benchmark media is already on the device. Thermal adaptation runs on API 29 and above and does nothing below.
- (constraint) C13 (AD-12): Data mints one opaque id per session and per event. Stored instants are UTC epoch milliseconds. Exports render those instants as ISO-8601 UTC.
- (constraint) C14 (SPEC §1, §19, DESIGN): The app is ViNet, package hu.toliver.vinet. The mark is the grape-leaf drawing, chrome is vine and sky, and the wordmark is Fraunces.

- (decision) 2026-11-08 A fix worse than maxAccuracyM is dropped from the join and from the distance.
